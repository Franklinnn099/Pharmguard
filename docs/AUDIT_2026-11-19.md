# PharmaGuard — Technical Audit (2026-11-19)

Auditor: Claude Code (taking over from the Antigravity-built prototype, commits `e221536`..`794ddca`).
Scope: entire repository, all source, tests, docs, Colab notebook, dependency pins, git history.
Method: full read of every file, test-suite run, plus targeted probes with controlled inputs
(probe script kept outside the repo; every number below was measured in this session unless marked *unverified*).

Measurement environment: Windows 11 laptop, **CPU only (no CUDA)**, Python 3.13.2, torch 2.10.0,
ultralytics 8.4.215, gradio 6.32.0. **No measurement has yet been taken on Colab GPU or through a real browser.**

---

## 0. Summary

The codebase is a clean, readable, modular skeleton (~1,600 lines of source, 20 passing tests). The
module boundaries (detector / tracker / behaviour / alerts / annotator / UI) are sound and worth keeping.

However, several documented claims are not true. The behaviour logic would cause alert spam on ordinary
shoppers, would never detect a person sitting at a laptop webcam, and leaves out most of what the mandate
asks for (hands, bag/pocket regions, scoring). The streaming path has an unmeasured server-side
bottleneck of about 0.5 s per frame. Nothing has been run end-to-end on Colab or through a real browser.

**Verdict:** keep the architecture, fix the streaming path first, then rebuild the behaviour engine and
alarm/event layers on top of it. None of these changes requires deleting a whole module.

## 3. Incomplete (mandate requirements with no implementation)

- **Hand/wrist proximity to shelf.** No pose model. The mandate's core behaviour signal is missing.
- **Bag/pocket regions and shelf→bag movement sequences.** Not started.
- **Suspicion scoring.** None; each rule fires a fixed-severity alert independently.
- **Audible alarm, acknowledge/reset, manual alarm test.** None.
- **Event record fields:** camera id, suspicion score, evidence clip. None. Persistence is a JSONL append in CWD.
- **Persistent database.** None (JSONL only, on ephemeral Colab disk).
- **Zone configuration UI.** Only confidence and dwell sliders; zones are hard-coded in config defaults.
- **End-to-end latency measurement** (browser → Colab → browser). None.
- **Staged scenario test protocol** (mandate §6). None.

## 4. Behaviour-engine defects (would fail the "no alarm for ordinary interaction" criterion)

Measured with a controlled clock and synthetic tracks at 10 FPS:

| # | Scenario | Result |
|---|---|---|
| B1 | Shopper **walks past** the shelf in ~1.5 s | **WARNING "RAPID RETREAT"**. Any 0.5–2.5 s pass through the zone polygon fires. |
| B2 | One shopper browses for 45 s (one incident) | **4 separate ALERTs** (re-fires every 10 s). |
| B3 | Two shoppers at the shelf for 30 s | **9 alerts** (6 dwell, 3 congregation). |
| B4 | **Person seated at a laptop webcam** (box bottom = frame bottom), in front of the default zone for 10 s | **0 zone entries, 0 alerts.** The feet point `(cx, y2)` is at y=1.0, below the zone's 0.85 edge. **The December webcam demo cannot trigger with the current rule.** |
| B5 | Two zones, person only in zone A | Both zones shown **OCCUPIED** (`pipeline.py:142-145` uses a per-person flag, not per-zone). |
| B6 | Single-frame false positive | Gets a permanent ID immediately (no activation confirmation). |

Root cause for B4: the feet-on-floor rule in CLAUDE.md §4.4 is correct for ceiling CCTV with full-body
views. It is wrong for a laptop webcam, where the shelf is a vertical plane in front of the camera and the
relevant signal is **hands**, not feet. The zone semantics need to depend on the camera geometry.

## 5. Architectural weaknesses

1. **One global pipeline shared by all browser sessions** (`ui.py` closure). Two viewers on the public link
   interleave frames into the same tracker, which corrupts IDs and dwell state.
2. **Wall-clock `time.time()` inside behaviour/alerts.** Makes deterministic tests impossible; existing
   tests work around it by mutating private dicts.
3. **Frame-count-based lost-track buffer (30 frames).** Means 1 s at 30 FPS but 6 s at 5 FPS. Should be time-based.
4. **Every frame re-renders two HTML panels and 6 textboxes.** Unnecessary websocket payload and DOM work per frame.
5. **Tests write to the production audit log.** Confirmed: one `pytest` run appended an alert to
   `logs/pharmaguard_alerts.jsonl`. All 5 existing entries in that file are test artefacts.
6. **Silent failure** in `AlertManager._persist_alert` (`except Exception: pass`). No logging module is used anywhere.

## 6. Dependency conflicts

- `requirements.txt` pins `gradio<=5.6.0`, `ultralytics<=8.3.40`, `supervision<=0.25.0`.
  The environment that produced the "20 passing" result has **gradio 6.32.0, ultralytics 8.4.215,
  supervision 0.31.7**. `pip install --dry-run -r requirements.txt` would **downgrade** gradio to 5.6.0
  and ultralytics to 8.3.40. **The pinned set has never been tested.** The Colab notebook installs exactly that set.
- `scipy` is imported directly (tracker) but not declared (it arrives transitively via ultralytics).
- `supervision` and `lap` are declared/installed but unused.
- *Unverified, check before relying on it:* gradio 5.6.0 predates several published security fixes in later
  5.x releases. That matters because the app is exposed on a public share link.

## 7. Security & privacy

1. **Video of real people traverses Gradio's public share relay** (`*.gradio.live`, third-party infrastructure).
   That is acceptable for a staged demo with consenting participants, but not for real pharmacy footage.
   Document this, and only use it with consenting actors.
2. Ephemeral password printed to stdout. Acceptable, but see Risk R2 (it may not be visible in Colab).
3. `--auth-pass` CLI flag exposes the password in process listings. Prefer env/Secrets only.
4. Single shared session: any authenticated viewer sees and affects the same stream state.
5. Planned evidence clips (Drive) will need a retention policy and a note on consent/signage. No faces are stored today.
6. Alert/event HTML is built by string interpolation. Inputs are currently trusted config values, but they must be escaped once zone names become user-editable.

## 8. Performance bottlenecks (measured, CPU laptop)

| Stage | Measured | Note |
|---|---|---|
| **P1 Gradio output encoding (default WebP)** | **527 ms @1280×720**, 112 ms @640×360 | Not covered by `benchmark.py`. Same frame as **JPEG: 13 ms / 6 ms**. One-line fix (`gr.Image(format="jpeg")`) plus server-side downscale. Likely the dominant real-time limiter. |
| P2 YOLOv8n detection, CPU | ~130–180 ms | GPU figure on Colab is unmeasured. |
| P3 Tracker + behaviour | < 0.1 ms | Negligible. |
| P4 Browser→server input transfer/decode | **unmeasured** | Must measure in a real browser. |
| P5 Gradio streaming back-pressure | **unknown** | With `stream_every=0.04` and processing >40 ms, it is not yet known whether frames queue (latency grows without bound) or drop. Must be measured in a real browser. |

## 10. Recommended plan (maps to mandate priorities)

**P1 Streaming (Nov 19–21)**
1. Re-pin `requirements.txt` to a tested set; drop unused deps; add `scipy`.
2. Output `gr.Image(format="jpeg")`, server-side resize to a configurable width (default 640).
3. Embed a capture timestamp; measure true E2E latency and processed FPS in browser; add drop-if-busy behaviour.
4. Fix notebook launch visibility; run on Colab T4; record real numbers in PROJECT_STATUS.
5. Isolate tests from the production log; add the `logging` module.

**P2 Tracking (Nov 20–21)**
- Fix the threshold overlap so the low-confidence stage is live (detector floor ~0.15, high split ~0.45).
- Loosen the IoU gate to ByteTrack defaults; add a real constant-velocity Kalman filter; time-based lost buffer;
  two-frame activation. Alternatively evaluate Ultralytics' built-in ByteTrack (`model.track`) behind the same interface.
- Scenario tests for crossing paths and occlusion.

**P3 Behaviour (Nov 22–25)**
- Add YOLOv8n-pose (same licence family, no training) for wrist keypoints.
- Per-person incident state machine: `IDLE → NEAR_SHELF → REACHING → HOLDING? → TO_BAG/POCKET → EXIT`.
- Weighted, configurable suspicion score with decay; alarm only above threshold; one alarm per incident.
- Zone types: `shelf` (hand-contact), `bag/pocket` (person-relative region), optional `floor` (feet rule for CCTV mode).

**P4–P6 (Nov 26–28)** Alarm latch + ack/reset + audible browser alarm + test button; SQLite event store on
Drive with evidence clip ring-buffer; dashboard zone editor and event review.

**Nov 29–30** Staged scenario runs (mandate §6) with measured false-alert / miss counts; fallback demo.
